## Carousel slides

1. We stopped measuring AI by speed. Here's what we measured instead.

2. Before: a ticket was "Integrate with Sensor X", a link to the API docs, and ten lines on what we knew. That was about it.

3. Developers got confused midway through. QA had no acceptance criteria and no context. And we skipped thinking about what the integration meant for the product as a whole.

4. Now: we give the workflow the sensor, the docs and the blurb. It reads the documentation with our code as context and builds a multi-card epic: connect, ingest, render.

5. It writes user stories for every sub-ticket and QA acceptance criteria to go with them. Then it helps the developer turn that scope into a locked-in delivery plan.

6. Not one line of that is code. It's the work that used to get done badly, or not at all, before anyone opened an editor.

7. 50-odd tickets built this way. Low rejection rate. Eight developers, seven months. No clean metric yet, and I say so in the post.

8. The time we saved writing code went back into planning what we write. Full write-up: nicalpi.com/blog/ai-measuring-wrong-thing

## Caption

Seven months ago I froze hiring to find out what AI would do to an eight-person dev team. The gain wasn't in the code. It was in the tickets. Eight slides on what changed, link to the full post in the first comment.
