I froze our tech hiring plan in January.

I told my CEO I wanted to understand what AI was going to do to my eight-person development team before I added people to it. I didn't have a prediction. I didn't know what we'd find.

Seven months later, here's the short version.

I assumed the finding would be about which tool won. Pick the best of the four coding agents we were trialling and go with it. I was wrong.

The output depended on the developer using the tool. Some were sharp with them and did an OK job. Some trusted them too much and sent back mountains of code we had to reject. The tools were good at writing code. They had no idea how we wanted them to work.

So I documented our workflow the way I'd onboard a new team of project managers, analysts, developers and QA, explaining to each of them how we wanted them to work with us.

That's where the gain showed up, and it wasn't speed.

A ticket used to be "Integrate with Sensor X", a link to the API docs, and ten lines on what we knew. Developers got confused midway through because there were decisions nobody had made. QA had no acceptance criteria. Now the workflow reads the documentation with our code as context, builds a multi-card epic, writes the user stories and the QA criteria, then helps the developer turn that into a delivery plan.

Not one line of that is code. It's the work that used to get done badly, or not at all, before anyone opened an editor.

When my CEO asked about productivity, I told him I wasn't interested in 10x. Maybe 1.25, maybe 1.5, because we now have agents dealing with the smaller items. The number I cared about was precision: how well we solve problems for our customers. I didn't want us to push more tickets. I wanted each ticket we pushed to be solving more and better.

I don't have clean metrics yet. What I have is the 50-odd tickets we've built with the workflow, the low rejection rate that came with them, and every senior developer, including the ones who resisted because they liked to feel in control, telling me after a few months that they're doing a better job.

Small sample, one team. But the time we've saved writing code is going back into planning what we write, and that was the intent from the start.

I've been quiet here for months because I was figuring this out. We've reopened hiring, and the full write-up is in the first comment.
