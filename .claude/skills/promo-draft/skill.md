# Promo — DRAFT

You coordinate drafting of social copy from an approved promo plan. The
`promo-drafter` agent writes; you present, iterate, and manage versions.

Read `.promo-memory/memory.md`, `.promo-memory/README.md`, and
`.writings-memory/memory.md` before acting.

## 1. Resolve

- Slug from `$ARGUMENTS`, else the single `.promo-memory/*/plan.md`. Several →
  ask. None → point at `/promo-plan`.
- `plan.md` missing → stop, send him to `/promo-plan`.
- Day number: `day N` drafts only that day's pieces. `all` drafts every day.
  Default: `all`.
- `drafts/` already has files → resume. Show what exists, what's missing,
  continue.

## 2. Draft

Dispatch `promo-drafter` with:
- The slug
- The day number(s) and their calendar entries from `plan.md`
- The original blog post path (the agent reads it for material)

**When drafting all days, split into two parallel batches** (e.g. days 0-2 and
days 4-10) dispatched as two separate `promo-drafter` agents in a single
message. This halves wall-clock time and the agents don't conflict because each
writes to different `day-NN-*` files. A single-day draft uses one agent.

The agent writes one file per piece: `.promo-memory/<slug>/drafts/day-NN-platform.md`
(e.g., `day-00-li.md`, `day-00-tw.md`, `day-01-tw-thread.md`).

For thread drafts, the agent writes each tweet on its own line, numbered.

**Humanizer pass** (optional, proportional to length). The `promo-drafter`
already reads `memory.md` and strips AI-tells, so short pieces are usually
clean. Run `humanizer:humanizer` only on LinkedIn posts over ~1,000 characters
(story posts, insight posts, longer quote-card captions). Skip it on tweets,
polls and thread tweets — they're too short for the humanizer to improve, and
the first run found nothing to change. Keep the humanizer's changes unless one
flattens a deliberate choice from the plan.

## 3. Present

Show Nic the drafts grouped by day:

```
### Day 0

**LinkedIn — Story post** (1,847 / 3,000 chars)
<full text>

**Twitter — Hook tweet** (214 / 280 chars)
<full text>

---
### Day 1
…
```

Include character counts against limits. Flag any piece over its limit.

For each day, note which assets are needed (from the plan's asset list) and
whether they exist yet.

## 4. Iterate

He replies with edits or approval per piece. Handle like `/writing-post`:

- **Small edits** → apply directly, keep his wording verbatim. Update the file
  in place (social copy doesn't need version history — it's short).
- **"Too corporate" / "sounds off"** → ask what specifically, then fix. If he
  names a pattern, add it to `.promo-memory/memory.md` under `## Social voice`.
- **"Skip this day"** → remove the entry from the plan and delete the draft
  files.
- **Platform swap** ("make the LinkedIn one a tweet instead") → redraft for the
  new platform's constraints.

## 5. Approval

Pieces can be approved individually or all at once. Mark approved pieces in
`plan.md` by adding `✓` to their calendar entry. When all pieces for a day
are approved, that day is done.

When the last piece is approved, set `status: approved` in `plan.md` and end
with: "All copy approved. Run `/promo-asset <slug>` to generate the visual
assets, or post the text-only pieces now."

If Nic approves text pieces but assets are still needed, remind him which days
need `/promo-asset`.

## Judgment

- LinkedIn copy is first-person, story-shaped, written for the feed (not a
  blog excerpt). It stands alone — a reader who never clicks through still
  got value.
- Twitter copy is hook-first, punchy, one idea. Threads build one claim per
  tweet. No tweet should need the previous one to make sense.
- Never put links in the main body of LinkedIn posts or tweets. Links go in
  the first comment (LI) or last tweet of a thread / a reply (TW).
- Character counts are hard limits, not suggestions. LI: 3,000. TW: 280
  (free) or 25,000 (Premium). Threads: 280 per tweet.
- The copy should sound like Nic, not like a social media manager. Same voice
  as the blog — plain, first person, confident about what he saw, honest about
  what he doesn't know. No hashtags unless he asks. No emojis unless he uses
  them naturally.
- Carousel slide text is written here too (as a numbered list of slide
  contents), but the PDF is generated by `/promo-asset`.
